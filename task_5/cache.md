### мотивация
внедрение кеширования позволит полечить проблему с долгой загрузкой страницы со статусами для MES. 

### решение
на мой взгляд лучше внедрить серверное кеширование следующим образом
запись производить непосредственно в базу без использования кеша
чтение построить по патерну Read-Through

при таком подходе если данные не изменились кеш будет раздавать всем пользователям одинаковые данные из себя.
после записи следующее чтение обновит кеш и мы придём к стабильному состоянию

cache_aside не подойдёт из-за неконсистентности данных, а при добавлении маленького времени жизни для поддержания консистентности в кеше не будет смысла
write_through не нужен, потому что нет смысла лишний раз дёргаь кеш
refresh_ahead так же не подойдёт по тем же причинам как и cache_aside

при таком подходе инвалидацию данных можно сделать на основе изменения данных - обновлять кеш, при обновлении статуса заказа, если в кеше хранятся заказы списком
также подойдёт инвалидация по ключу, если заказы в кеше хранятся поотдельности
по времени данные будут неконсистентные
